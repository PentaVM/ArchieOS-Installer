## Result

- `archie-lumen-design` is a dependency-free Rust rlib/staticlib: exact flattened eight
  source preset payloads, typed catalog, material/texture/quality policies, packed linear
  procedural surfaces, source geometries, rest-aware physics, bounded continuity and four
  shell geometries. The C ABI borrows caller buffers and retains no pointers.
- The existing native Qt host uploads the Rust output, observed instance state and local
  hybrid maps. Original sphere/material, cinematic framings, comparison, World and shell
  layout remain. GPU shaders and Qt/QML lifecycle are host exceptions, not a new browser.
- Delivered profiles are discovered by the running renderer and available through native
  settings and the existing CLI/voice contract. An acknowledged profile is not reapplied;
  shell defaults do not silently overwrite its source values. Explicit user changes work.
- Source regions corrections preserve the OS's eight semantic categories, twelve-dimensional
  composition, stable IDs, parents, domains and 420-node ceiling. No filesystem scanner,
  network authority, inference service or new permission is added.
- WSL Operator packages the same native renderer and read-only bridge. `archie-design`
  opens it through WSLg; `--preview` explicitly retains synthetic design boards. Opening
  the GUI cannot start privileged services or replace an observer. Missing projections
  remain unavailable. No live WSL image was regenerated or deployed.
- Main `917372596` is combined with PR head `35aff626` preserving dynamic catalog,
  strict atomic preset validation, synchronous ACK, CLI JSON, additive voice controls,
  shell lifecycle, per-view ownership and governor budgets. PR remains draft, no merge.

## Verification and limits

- CPU Rust tests for orb/design/displayd/shell-bridge: 130 passing, including 21 new
  design tests; voice without default features: 51 passing. Packaging: 46 passing.
- QML shell: 77 passing, including exact source value preservation and no duplicate ACK
  application. Local-file reading is enabled only in the fixture test environment.
- Native CMake build and four CTest suites include real shader execution under measured
  `llvmpipe` (LLVM23.1.1, 256 bits), OpenGL3.3Core: original, eight profiles and four shells.
  Synthetic two-node captures test drawing/compilation; they are not real OS observations,
  visual equivalence evidence, throughput benchmarks or GPU/hardware certification.
- WSL launch/package scripts pass `bash -n`. Independent source review found no remaining
  confirmed important defects. No production training/worker/watchdog/hold was modified.

Important fidelity boundaries: packed surface formulas and preset values are ported, but
CPU baking is not bit-identical to hardware GLSL arithmetic. The retained native lighting
and original/category geometry differ from Three.js PBR. Selective bloom currently weights
emission in the existing native bloom path; the source's separate low-resolution selective
mask/composite pass is not implemented. OS governor budgets take precedence over source
pixel-ratio/auto-quality requests; source-only scanner/capture/metadata controls do not
replace OS facilities. Source `visualBloomMask` is metadata in the original too. Accordingly
this commit does not certify exact pixel parity or completion of those fidelity differences.

NVIDIA, VirtualBox, installed ISO, WSLg/DRM, live Core/Cortex/IRIS/Stage/NeMo integration,
accessibility and performance/resource benchmarks still require their actual environments.
