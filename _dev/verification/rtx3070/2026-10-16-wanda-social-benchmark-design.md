## Separation and contamination controls

1. Build only a public development pilot first: 24 causal families with four variants each (96 prompts) to test coverage, scoring instructions and output collection. These are not superiority evidence and cannot later become sealed cases. This protocol's worked examples belong here.
2. Before final training, an independent case author/reviewer creates the sealed set outside the trainer worktree: initially 120 causal families, 24 per stratum: close relationships, workplace collaboration, sales/negotiation, group/reputation dynamics, and information gathering under ambiguous intent. Each has clean, irrelevant-noise, causal-counterfactual and cosmetic-renaming variants (480 prompts per arm). Families, not variants, are the statistical units. Add new scenarios with prospective collection rather than reusing famous public test questions.
3. Private source narratives and causal-family identifiers have disjoint train/development/sealed membership. Freeze SHA256 manifests for prompts, private scoring keys, split ancestry and protocol before any sealed call. Check exact and near-duplicate overlap with admitted training material, including book-derived scenarios and translations. A changed name or paraphrase is not an independent family. Hashes deter later edits; they do not prove absence of pretraining contamination.
4. Trainers receive training/development only. The collection process receives public prompts but no answer keys. Raters receive prompts and anonymized responses but no model identities. Mapping keys and sealed outcomes stay with the evaluator, outside trainer logs/caches. Do not put sealed plaintext in Git, a public PR, the implementation agent's context or the distributable WSL.
5. Freeze candidate/base/runtime hashes before evaluation. No prompt repair, target expansion, checkpoint choice or retry-until-success after looking at sealed performance. New optimization after seeing scores needs a new untouched sealed set; mark the old one exploratory.

This is controlled held-out evaluation, not a guarantee that proprietary pretraining never included an overlapping idea. Report that limitation explicitly. If independent case authors/raters are not yet available, report a development evaluation rather than calling it blind.

## Inputs and fair collection

Give every arm the same admitted evidence, user objective, action options and concise response instructions. Do not give Wanda privileged retrieved context or a richer system prompt. No browser, memory, Core tools or external side effects in the primary comparison. A separate end-to-end Wanda integration suite checks its existing recommendation JSON; the primary social task uses common concise decision fields and scores content even if formatting fails. Report format errors independently, without favorable retries.

Required answer: chosen action; concise evidence-linked justification; alternative explanation; expected consequences and relational cost; missing information that could change the decision; and probabilities only for a defined forecast event. In a second free-response subset, allow a better action than the supplied options and rate it without forcing the original key.

Use the same visible answer limit (600 words), admitted input ceiling (4096 tokens, with no silent truncation) and total generation cap (4096 output tokens including provider reasoning when counted that way). Record requested and actual settings, hidden reasoning usage when exposed, input/output tokens, truncation, time to complete, GPU/RAM peak and spend. Providers tokenize and budget reasoning differently; matching an effort label does not equal matching compute. Label the primary condition as bounded inference and publish these differences. Report cap exhaustion separately and include it in intent-to-evaluate results.

Claude5.5 adaptive thinking stays enabled as required by its API; request medium effort. GPT6.1 Sol requests medium reasoning. Bonsai native reasoning mode and template identity are frozen and recorded; do not disable reasoning only for a convenient local result. Do not request provider-unsupported temperature/forced-tool settings. A pilot selects feasible fixed settings before sealing; changes require a new condition, not replacement of unfavorable outputs. Greedy/native seed where supported; otherwise log nondeterminism. Run the pilot twice to estimate variability. Primary sealed collection is one response per prompt per arm; additional repeats are a separately budgeted sensitivity study, not extra independent cases.

Start remote runs with at most two public pilot prompts per provider and a conservative preflight cost reservation using configured provider rates. Reserve worst-case input/output cost before every request; refuse dispatch when the declared run cap would be exceeded. Suggested initial remote cap US$2, explicit cap US$25 for a later full run after actual pilot usage is known. Never spend the full-run budget merely because the cap exists. No automatic full run before access, cases, ratings and candidate are ready. Load local models sequentially under existing GPU leases; do not fit 9B and27B simultaneously or interpret offloading as an identical latency condition.

Transport retry: at most two retries on transient network/429/5xx, same request/settings, logged. Never retry content quality, refusal, parse failure or truncated reasoning. Retain all attempts with one declared final transport outcome. Count infrastructure failures separately from completed model decisions; do not silently remove hard cases.

## Measures and claim rules

Primary outcome: blinded paired preference for the better decision, assessed against the stated user goal and supported consequences. Two independent raters judge each comparison; randomized left/right order and balanced order across models; third adjudicator for disagreement. Keep initial ratings and disagreements as well as adjudication. Raters cannot also author the tested model's training targets. A tested model is not its own judge. Mask provider/model metadata, not substantive answer content; style may still reveal identity, so collect raters' identity guesses after scoring and report this limitation. Automated judge outputs, if later used, are explicitly secondary and audited against humans.

Rate six dimensions separately on anchored 0–4 scales: understanding of objectives/context; evidence and competing hypotheses; strategic action quality; immediate/delayed consequences; relational costs relative to the user's priorities; and uncertainty/information value. Anchor 0 = unsupported or ignores a decisive stated fact; 2 = plausible decision with a material omission; 4 = a feasible, evidence-linked decision covering the decisive tradeoff and what would change it. No points for length, grandiose certainty, agreeable tone, moral vocabulary or outputting valid JSON. Raters must cite the decisive case fact behind their judgment. No arbitrary weighted 'social IQ' composite.

Use pairwise score 1 for Wanda win, 0.5 tie, 0 loss; report wins/ties/losses and a clustered 95% interval on the mean, resampling complete families (10000 bootstrap draws, fixed seed20261016). Predeclare the three Wanda-versus-requested-model comparisons and control their one-sided superiority tests with Holm at familywise alpha0.05. Use a paired family-level permutation test for each comparison; report exact method and Monte Carlo seed/draw count if enumeration is infeasible. Overall superiority requires all three adjusted tests to pass and positive paired estimates. Never call an inconclusive interval a win. Publish effects by stratum and raw anonymized rating receipts; do not claim general social intelligence from this bounded set. Choose final sample size from development pilot variance and a declared minimum relevant effect before sealing; 120 families is an initial design size, not a power guarantee. Do not add cases until a desired p-value appears.

Secondary diagnostics: objective option/outcome accuracy where the scenario has a verifiable key; Brier score and reliability bins for forecasts with a defined binary outcome and known or prospectively observed resolution; noise/cosmetic invariance; correct response to causal changes; novel-family performance; invented-evidence rate; format validity; latency/resources/cost. Do not compute calibration against a rater's guess of a person's hidden feelings. Fictional resolved outcomes measure simulation calibration only. Real prospective outcome calibration needs consented independent observations and a separate collection protocol.

Do not demand that an answer change for every counterfactual. The private key states whether the changed fact changes the optimal action, the rationale, or only confidence. Noise stability without evidence sensitivity is not robustness. A refusal is a response to be rated for usefulness on the actual case, not an automatically injected moral penalty or reward. Wanda has no extra moral reward model.

## Worked development examples — never sealed

**Deadline and relationship.** User wants a deliverable Friday while keeping collaboration workable. Colleague has missed two commitments, says 'ya veo', and has a known scheduled outage today. The message bundle also contains football results and an unrelated angry comment from another chat. Compare: short clarification with a concrete contingency; passive waiting; a hostile accusation. A good answer uses the commitments and deadline, does not infer contempt from 'ya veo', and proposes a feasible fallback. Counterfactual: the deadline is in20minutes and only the colleague has the required credential. The urgency/information cost changes; the outage remains evidence, not proof of intent. Cosmetic changes must not flip the conclusion.

**Sales objective changes.** A repeat customer questions a quote and mentions a lower competitor price without sharing scope. User prioritizes renewal margin over closing today. Distinguish verifying comparable scope, conceding immediately, and creating urgency. Counterfactual: user instead needs immediate cash and has explicitly accepted a lower margin floor. Evaluate the recommendation against the changed goal and stated floor; do not make 'never discount' a rule. Irrelevant praise and emojis must not choose the action.

**A friendly heuristic fails.** A friend explicitly asks for concrete feedback about repeated missed appointments, while the user wants a reliable future arrangement. A polished response containing only praise and generic empathy is a negative example despite sounding kind. Another variant includes a credible temporary constraint; a different feasible arrangement may then beat confrontation or silence. Evidence supports several explanations, so certainty about motive is not rewarded.
