## Outcome and approach

Keep the existing router and provider-neutral runtime. Promote provider configuration from CLI-only bookkeeping to a shared validated catalog, add native Anthropic Messages transport, and use official process-managed Codex account/session protocols for the owner's CLI connection. Never read another app's token storage. A loopback harness is labelled by where its model actually runs. API credentials remain environment/broker-backed and are never memory content. Anthropic subscription use in a third-party product remains gated by provider approval; a native API transport is implemented independently of that entitlement.

Use existing PostgreSQL/StateStore and filesystem Vault rather than a parallel memory database. Add an explicit exact-domain execution/session binding and attributed receipts with schema migration, CAS and checkpoint/outbox consistency. Recall resolves committed evidence through the same domain boundary after reopening; model outputs and hypotheses never turn into verified facts just because they were stored. Refresh Core constraints on every request/resume.

For Google Harness², retain the pinned upstream engine at `1cfe254e8d25b15f37048c3730134686abe60335` (Apache-2.0). An isolated Python worker implements explicit Archie adapters around upstream Propose–Probe–Compose, selection/reflection and persistent library; the runtime/router supplies stage inference. Do not run upstream reference executors which bypass permissions on the host. Policy, domains, leases, credentials and hard budgets remain outside the editable harness. Preserve complete adopted trees and evidence, scoped separately by authorization domain and task family. Upstream selection is not a claim of improvement: Archie has a separate admission/baseline fallback gate.

Alternatives rejected: replacing Core with a new agent framework would duplicate authority; treating provider CLI version/auth as working inference would not meet the brief; a Rust-only PPC sketch would not be actual Google upstream integration. Keep Rust as the application control plane and the upstream Python worker as a replaceable, bounded dependency.

## Contracts and ownership

1. Runtime catalog (`archie-model-runtime::provider`): one shared `ProviderSpec`/load-save/validation; `archie-workstation::provider` remains a compatibility re-export. Configuration and discovered model IDs yield validated descriptors with explicit unknown/unmeasured defaults. Catalog loading rejects duplicate/conflicting identities. `Routed::from_paths(models, providers)` loads both sources. Cloud inference remains Cloud even behind a local child or proxy.
2. Native transports: existing `Question`, `ChatRequest`, `ToolChatRequest`, `StreamEvent` remain the common model boundary. Add native Anthropic wire mapping; never send OpenAI wire JSON to it. Total deadlines cover retries, backoff, streaming and failover; cancellation drops the active request/owned child. Incrementally bound input/output, reject malformed terminal statuses, and do not retry partially emitted turns.
3. Durable inference contract: exact ContextDomain + focus/task/objective + runner/provider/account identity. Persist opaque external session IDs, input/output digests, admitted evidence references, observed status/usage and sealed result references. No raw credential, rendered private prompt or Veil mapping is persisted. Failed/cancelled work stays failed/cancelled. Commit receipt and checkpoint consistently using existing PostgreSQL transactions/CAS/outbox. Migration is additive and hash-verified; never rewrite schema v1 in place.
4. Unified service/CLI (root integration): configured catalog -> fresh admitted task context -> selected API/process runner -> attributed result -> Vault/State checkpoint -> scoped recall/restart. Provide executable CLI commands for configuration/discovery, account status/login, actual bounded inference, recall and Harness² tasks. Existing probes remain distinguishable diagnostics. No model-produced tool can bypass the existing executor/Policy/lease path.
5. Codex adapter: managed official app-server owns authentication. Archie speaks initialize/account/read/thread/start-or-resume/turn/start/interrupt over bounded stdio JSON-RPC; opaque thread IDs are persisted only under the same account/provider/domain. Disable unneeded tools and refuse approvals rather than adding blanket bypass flags. Authentication/catalog availability is distinct from a successful real model turn.
6. Harness² adapter: versioned Rust↔worker request carries run/task/focus/domain/policy refs, pinned upstream/config hashes, evidence and global limits. Runs use own staged directories and bounded authenticated local transport to the chosen runtime. Never execute generated scripts/plugins on the host or mutate the checkout. Save real upstream R/P ledger plus all extra selection/reflection/retry usage. Second tasks can retrieve only same-domain admitted experience. Resume identity includes task input/model/base/config hashes.

Root owns CLI/Core wiring, official Codex process adapter, aggregate service, shared manifests and integration verification. Provider implementer owns model-runtime modules and workstation provider compatibility. Persistence implementer owns memory/PostgreSQL/StateStore additive modules and migrations. Harness² implementer owns worker/bridge/upstream integration modules. All shared interface changes are announced before consumers are written.
