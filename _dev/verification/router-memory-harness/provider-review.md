## Important findings

1. **[P1] Preserve known cloud identity when generating compatible-provider descriptors.** `core/crates/archie-model-runtime/src/provider.rs:152–164` assigns every compatible provider `ProviderKind::OpenAiCompatible` and copies its declared locality/clearance. Validation delegates to the endpoint, whose only host/locality constraint is Local => loopback (`src/lib.rs:120–131`). This loses fixed cloud identity for builtins such as OpenAI and Nebius, allowing a contradictory cloud declaration to pass validation and privacy gates.

   Source-level repro, requiring no credential read: take `builtin_provider("openai")`, add one model, set `locality = Locality::Fabric`, keep `https://api.openai.com/v1/`, then call `validate()`, `endpoint()` and `descriptors(&[])`. All succeed; the descriptor permits `PrivacyGrade::Sensitive` despite unknown retention because Fabric is treated as operator-controlled. A known cloud-backed loopback proxy can similarly use the builtin OpenAI identity with `base_url = "http://127.0.0.1:PORT/v1/"`, `locality = Local`, and no credential source (the proxy owns authentication). Its descriptor admits Restricted and `ask_private` takes the Kept path, reporting `left_the_machine=false`.

   This is a contradictory deployment declaration/configuration validation defect, not a claim that an untrusted model can edit operator configuration. A generic loopback server's backend cannot be verified from wire address alone; explicit operator admission remains necessary. The design nevertheless explicitly requires known cloud inference to remain Cloud behind proxies. Preserve/enforce fixed cloud identity independently from wire protocol and transport address; reject reserved builtin cloud identities or known cloud service endpoints labelled Local/Fabric. Keep genuinely generic local/fabric deployments possible through an explicit trusted deployment claim. If cloud proxies on HTTP loopback are supported, allow that transport without relabelling physical locality. Add regressions for OpenAI/Nebius builtin locality overrides, known cloud HTTPS + Fabric, and known cloud loopback proxy + Restricted/Secret denial. Existing remote-HTTPS-as-Local test does not exercise either bypass.

2. **[P2] Recognize Anthropic refusal as a terminal provider outcome.** `core/crates/archie-model-runtime/src/anthropic.rs:92–100` rejects `stop_reason: "refusal"`, so both JSON decoding (`:112`) and SSE message_delta processing (`:357`) classify a normal native terminal response as a protocol failure. Through `Routed::ask_among` (`src/routed.rs:488–491`), that error causes another provider to receive the request; the refusal and its observed usage are discarded. In a stream, refusal text can already have reached the callback before the parser reports failure.

   Repro fixture: an otherwise valid assistant JSON response with a text block, model, usage and `stop_reason:"refusal"` returns NativeProtocol. In the existing valid SSE fixture, replace end_turn/tool_use with refusal after a completed text block; message_delta returns Malformed instead of permitting message_stop. Anthropic documents refusal as a normal HTTP 200 stop reason, distinct from request errors: [official stop reasons](https://platform.claude.com/docs/en/build-with-claude/handling-stop-reasons#refusal). Preserve refusal as a recognized terminal outcome, with observed content/usage when supplied, and prevent automatic transport failover from concealing it. This need not mark the task successful or add server-tool/pause-turn support. Add JSON and split-SSE refusal tests plus a routed fixture proving no automatic second-provider call.

## Focused re-review after fixes

Re-read only the two finding fixes, their regressions and the provider report's Independent review fixes section. Remote remains `PentaVM/ArchieOS-Nvidia`. No tests/builds or credential/provider/hardware checks were rerun.

- **P1 — ADDRESSED.** `provider.rs:64–72` rejects non-Cloud locality for reserved cloud provider IDs, case-insensitively. `lib.rs:128–142` independently rejects known cloud service hosts labelled Local/Fabric, normalizing case and trailing dots. Generated OpenAI/Nebius registrations retain fixed cloud provider kinds (`provider.rs:160–168`); endpoint selection preserves configured credentials and Cloud locality. Regressions cover reserved IDs, known HTTPS cloud hosts with Fabric under a generic alias, fixed descriptor identity, private-grade denial and HTTPS loopback cloud proxies. Positive tests retain explicitly operator-admitted generic Local/Fabric deployments. No assertion is made that a generic proxy's actual backend can be discovered from its address; HTTP Cloud proxies remain deliberately unsupported.
- **P2 — ADDRESSED.** `anthropic.rs:97` recognizes refusal; JSON permits an empty terminal refusal while retaining supplied text/usage. The same terminal mapper feeds split SSE, which still requires message_stop and withholds invalid tool calls. `routed.rs:569–589` preserves `finish_reason`, including an empty refusal, and the shared production fallback loop returns that semantic outcome instead of trying the next provider. The native HTTP fixture traverses the production fallback/conversion functions, checks content/status/completion usage, and proves the second real TCP listener receives no connection. Root accepted the additive `Answered.finish_reason` field and owns subsequent service receipt classification.

Reported fresh proof is consistent with the reviewed regressions: catalog RED 5 passed / 3 failed; native/routed refusal RED 3 failed; GREEN **98 passed, 0 failed, 2 ignored**, strict runtime Clippy exit 0 and scoped formatting checks. This is implementer-reported execution evidence, independently inspected source/fixture coverage rather than a second execution.

Focused verdict: **both Important findings addressed; no new Important/Critical breakage found in these fixes**. The earlier changes-requested verdict is superseded for these two findings only. Unfinished root service/Core integration and previously excluded work remain outside this review.
